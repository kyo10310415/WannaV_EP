# OBSマスター（ツール第1弾）

## ツール共通の使いやすさ・生徒別利用回数

- ヘッダーのツールリンクはスペシャルコンテンツ直後に表示する。各相談ページには使い方・使用例を表示。使用例を押すと入力欄にコピーするが送信はしない。入力済みの文章があれば置き換え前に確認する。
- 初期見出しは「相談を入力してください」。新規相談ボタンを押さずに送信でき、初回送信時に本人・ツール別の会話を自動作成する。同じ会話では文脈を維持し、「＋ 新しい相談」は別の話題を分ける用途で残す。ゲーム配信戦略の初回モード選択文は、未作成の入力状態でも表示する。
- 生徒管理一覧に当月・累計の合計とツール別回数ボタンを表示。既存の`tool_usage`でstatus=completedの送信を1回と数え、入力案内も含める。新しい相談の作成、処理中、失敗、未完了は除く。AI内部の複数呼び出しは1送信として扱う。当月は日本時間の月初以上・翌月月初未満。会話削除後も利用集計は残る。本アプリに記録された利用のみで、カスタムGPTの利用は含まない。
- 既存`GET /api/students`の表示ページに含まれるuser_idだけを1クエリーで集計し、tool_usage配列として追加。未利用は6ツールすべて0、アカウント未作成はnull。管理者・セールスの既存一覧権限と、クルーの担当生徒限定を維持。会話本文・添付は公開しない。DB変更・環境変数追加なし。

## 第6弾：YouTubeゲーム配信 戦略分析官

失敗時は`Game strategy analysis failed`に処理段階（container_create/file_upload/file_link/csv_audit/public_research/strategy_answer）、固定エラーコード、HTTPステータス、許可リスト内のAPIエラー種別だけを記録し、画面にも同じ識別情報を表示する。APIエラー本文・例外メッセージ・CSV・会話・認証情報は出力しない。未完了応答も処理段階を記録し、自動再送しない。

モード切り替え後は、最新の確定モードを最終回答の指示へ明記する。探索では一般YouTubeヘルプだけで調査を終えず、市場の実在ゲーム・更新情報を検索する。探索回答に「新規候補（新規ゲーム候補）」と「最優先テスト」がない場合は`ANSWER_MODE_MISMATCH`で停止し、別モードの回答を成功として保存しない。自動の有料再試行は行わない。

- 一覧カードから`/tools/youtube-game-strategy`。APIは`/api/tools/youtube-game-strategy/...`。専用指示・初回文・入力受付は`src/services/youtubeGameStrategy.js`。
- 新しい相談では指定のモード選択文だけを自動表示（APIなし）。①/1/１でチャンネル詳細分析、②/2/２で新規ゲーム探索。選択後はチャンネルURL＋内容が異なるCSV3件が揃うまで指定のデータ提出案内と受領数だけを返す。分割送信・モード切り替えで同じ入力を再利用できる。同じCSVのコピーは1件として扱い、別チャンネル・4件以上の異なるCSVは新しい相談へ案内する。
- チャンネルURLはHTTPSのyoutube.comの`/@...`、`/channel/...`、`/c/...`、`/user/...`のみ。動画URL・外部URL・認証付きURLは対象外。クエリーを除いて公開チャンネルURLを正規化する。
- CSVは1回3件・各2MBまで（会話全体10MB上限は維持）。UTF-8、読み取れない場合はShift-JISとしてデコードしUTF-8で保存。NUL・空データ・CSV以外は拒否。列・行・期間・結合キー・3種類の役割の本点検はPythonで行い、ファイル名では決めない。意味・期間・分類が曖昧なら質問を返して停止する。文字コードの補正は意味の補完ではない。Excel・ZIPは非対応。
- 本分析は①Code InterpreterでCSV点検・実計算（最大8呼び出し）→②公開チャンネル・市場のWeb調査（最大3呼び出し）→③計算結果と公開情報からモード別の戦略提案。検索用の別リクエストには正規化した公開チャンネルURLとモードだけを渡し、CSV・集計結果・会話本文は渡さない。計算コンテナは外向きネットワークを無効化する。
- 指標を集客／視聴の質／ファン化に分け、加重CTR・登録者/1000再生・n・欠損・重複・合計行・少数標本・時系列を点検する指示を固定。相関を因果にせず、公開情報と内部Analyticsを区別。候補は根拠が取れたものを最低10・可能なら20件目標とするが、取得不足時に水増ししない。公開YouTube全履歴や市場全体の網羅は保証しない。
- OpenAI Docsの[Code Interpreter](https://developers.openai.com/api/docs/guides/tools-code-interpreter)、[Files](https://developers.openai.com/api/reference/resources/files/methods/create)、[Containers](https://developers.openai.com/api/reference/resources/containers/methods/create)に基づく。既存`OPENAI_API_KEY`と`OPENAI_OBS_MODEL`を共用し、モデルとプロジェクトにはResponses API・Code Interpreter・web_search・JSON Schemaの利用対応が必要。新規環境変数・依存・DB列は追加しない。
- 利用ごとに1GBの一時コンテナとCSVファイル3件を作成。処理後は成功／失敗とも削除を試みる。アップロードファイルは1時間の有効期限、コンテナは20分無操作で失効する設定を付ける。障害時は削除完了を保証せず、安全な固定文でログを残す。`store:false`はOpenAIの全保持をゼロにする保証ではない。
- 入力案内は`local-intake`（token/検索/費用0）。本分析の最大3つのモデル応答のtoken・検索回数を合算し、Code Interpreterの追加料金を含む金額は未算出。利用上限は他ツールと同じ全ツール合算の本人1日30送信・全体月10000送信。失敗・入力案内も送信回数に含み、最初の自動モード選択文だけは送信回数に含めない。
- 計算・検索・回答が未完了なら成功扱いせず、自動再試行しない。入力受付済みの内容は履歴に残す。途中で使用量が不明になったら不明扱いとし、ゼロ円とは表示しない。全処理は最大7分＋片付け、画面は最大8分を案内。同期HTTPのため、ホスティング側のタイムアウト・ブラウザー切断・再起動後の再開は未対応。切断時は送信を繰り返す前に履歴を確認する。
- サムネイルは組み込みImageGenで生成。「ゲームをしている女性VTuber、コントローラー・ヘッドセット、ゲーム配信スタジオ、YouTubeゲーム配信 戦略分析官の文字、16:9」。保存先`public/images/tools/youtube-game-strategy.webp`。
- テストはAPIモックと隔離PGlite。実APIのPython実行結果・市場情報の取得精度・モデル利用権限・実ブラウザー操作・Render長時間応答は未確認。ゲーミフィケーションと脆弱性対応はこの差分に含めない。

## 設定

- `OPENAI_API_KEY`：サーバー用のOpenAIプロジェクトAPIキー。ブラウザー・Git・チャットへ貼らない。
- `OPENAI_OBS_MODEL`：そのプロジェクトで利用可能な、Responses APIの画像入力とweb_search対応モデルID。未設定なら送信不可。利用可能モデルを確認してから設定する。
- 概算費用：`TOOLS_INPUT_USD_PER_MILLION`（非キャッシュ入力100万token単価）、`TOOLS_CACHED_USD_PER_MILLION`（キャッシュ入力100万token単価）、`TOOLS_OUTPUT_USD_PER_MILLION`（出力100万token単価）、`TOOLS_SEARCH_USD_PER_CALL`（検索1回単価）。全てUSD。未設定・不正なら金額は未算出。0は無料単価として扱う。

単価は利用モデル・価格体系に合わせて管理者が設定。各リクエスト時点で概算を保存する。過去の単価変更を遡及適用しない。税・為替・段階料金・プロバイダー独自の検索課金単位の差異は未反映。検索回数はレスポンスのweb_search_call数による概算。実請求額ではなく、OpenAI請求管理と照合が必要。他のアプリ・カスタムGPTの使用量は取得しない。

## 保存・プライバシー

新規4テーブルを既存schema初期化から作成する。既存の学習・同期テーブルの意味を変更しない。
会話本文・添付はアプリのPostgreSQLに保存。公開uploadsは使わず、本人のBearer認証付きAPIだけでダウンロード。画像はPNG/JPEG/WebPのシグネチャ、ログは拡張子・UTF-8・NUL不在を検査。画像内容の完全デコード検証やウイルス検査ではない。
会話削除で本文・添付を削除。削除済み会話の識別子と利用集計は残る。バックアップ内の保持はDB運用に従う。
Responsesにはstore:falseを指定するが、これはプロバイダーの全保持をゼロにする保証ではない。送信前にキー・パスワード・個人情報を隠す案内を表示。
会話を続けるたびに、その会話の本文・添付を再送して文脈を保持する。文脈が長いほど入力費用が増える。

## 上限・失敗

- 本人1日30送信（日本時間）、全体月10000送信。失敗・結果不明も上限に数える。金額のハード上限ではない。OpenAIプロジェクト側の利用制限・監視も設定する。
- 会話100件／本人、40メッセージ／会話、添付合計10MB／会話。
- 文章6000文字、添付2件・各2MB、ログ各100KBまで。DB容量を消費するため使用量監視・削除運用が必要。既存の小容量DBでは本番利用前に空き容量を確認する。
- プロセス内同時送信4件、同一ユーザー1件。DBの会話ロック・全体予約ロックで多重予約を防止。
- 回答上限2500出力token、検索最大3tool call、API待機90秒。検索を必須とし、検索失敗時に未確認情報を回答済みとして出さない。
- 送信UUID重複は409で拒否。接続障害・保存失敗で自動再送しない。provider応答を得られなければunknown、プロセス中断はpendingに残り、token・費用は不明と表示。課金ゼロとは主張しない。
- 添付容量・利用回数の制限はあるが、APIキー流出後の外部利用は防げない。キーはプロジェクト専用とする。
