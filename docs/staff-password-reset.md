# 管理者用アカウントのPWリセット

管理者用アカウント画面には、既存の「PW変更」と別に「PWリセット」を表示する。管理者だけが管理者・クルー・セールスのアカウントをリセットでき、生徒は対象外。確認後にパスワードを1111のハッシュへ変更し、password_changed_atをNULLへ戻す。次回ログインでは既存のパスワード変更画面へ進み、変更前は保護APIを使えない。初期パスワード1111をそのまま再設定することはできない。既存のPW変更は変更済み状態にする従来の動作を維持する。

リセットごとにスタッフ用リセットnonceを更新し、以前のスタッフJWTは保護API・ユーザー情報取得・パスワード変更で拒否する。新規ログインと変更完了JWTへnonceを含める。パスワード変更保存時もnonceを照合し、古いセッションで後のリセットを上書きさせない。スタッフ認証には主キーによるnonce照会を追加する（生徒認証には追加しない）。自分自身をリセットした場合はブラウザのトークンを削除してログイン画面へ戻す。

APIはPOST /api/admin/users/:id/reset-password。初期パスワードはクライアント指定を受け付けない。起動時マイグレーションでusers.staff_password_reset_nonce UUID列を追加する。認証情報・ハッシュ・nonceをログに出力しない。

1111は推測しやすいため、対象者へ速やかに連絡し、本人に変更してもらうこと。リセット自体は本番アカウントに対する操作なので、実行対象を確認する。

## 生徒用アカウント管理

生徒一覧にも既存PW変更とは別の「PWリセット」を表示する。管理者だけがPOST /api/admin/students/:id/reset-passwordを実行できる。セールス・クルー・生徒は実行不可。対象も生徒に限定し、スタッフ用APIの対象制限は維持する。

生徒も1111へ戻し、変更済み状態を解除して次回ログインの変更を必須にする。変更前は保護APIを使えず、1111をそのまま再設定することもできない。旧JWT・メディア用JWT・旧JWTによるパスワード変更を拒否するため、既存のstaff_password_reset_nonce列とstaffResetNonceクレームを互換性維持のため同名で再利用する。新しいDB列は追加しない。認証のnonce照会は生徒にも適用する（主キーによる単一行読み取り、キャッシュは使わない）。既存の生徒PW変更・Notion初期アカウント作成・スタッフのリセット操作は維持する。
